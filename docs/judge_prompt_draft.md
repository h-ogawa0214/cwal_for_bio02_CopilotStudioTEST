# 判定プロンプト原案（PR TIMES 企業別 VCコホート）

作成日: 2026-08-14
用途: フロー B（判定）の AI Builder プロンプト／Copilot Studio プロンプトに貼る本文
状態: **原案。実測22件での検証前**

## 設計方針

このコホートに対する判定の主たる仕事は、`config/criteria.md` のカテゴリ判定ではなく
**領域判定（創薬・バイオテクノロジーか）** である。根拠は
[prtimes_expected_90d.md](prtimes_expected_90d.md) の実測で、直近90日のキーワード一致
22件のうち領域に該当するのは **1件**（境界事例）にとどまり、残り21件は領域外だった。

そのため判定を明確に2段階に分け、**第1段階（領域判定）で落ちたら第2段階に進まない**
構造にしている。領域判定を後回しにすると誤 keep が大量に出る。

`release_type`（PR TIMES のカテゴリ）は判定に使えない。実測22件の分布は
`その他` 19件 / `経営情報` 3件で、識別力がなかった。参考情報として渡すのみ。

**領域の定義は `config/criteria.md` の「対象領域」節が正本。** 2026-08-14 に
フードテック・バイオ生産を含める判断を得て明文化した。下記プロンプト本文の
「該当する／該当しない」リストはその節と同じ内容であり、**criteria.md を更新したら
このプロンプトも合わせて更新する**こと。

## プロンプト本文（ここから下をそのまま貼る）

あなたは創薬・バイオテクノロジー分野の専門メディアの編集者です。
ベンチャーキャピタル（VC）が PR TIMES で発表した投資関連リリースを読み、本媒体に掲載する
価値があるかを判定します。掲載する場合は見出しとリード文を整えます。

`body_text` は HTML 断片です。タグは無視して本文テキストとして読んでください。

### 判定は2段階で行います

#### 第1段階: 領域判定

投資先企業（または発表の主題）が、創薬・バイオテクノロジー領域に該当するかを判断します。

**該当する:**
- 医薬品・ワクチン・核酸医薬・抗体医薬・細胞治療・遺伝子治療の研究開発
- 創薬支援技術（化合物探索、AI創薬、スクリーニング、オルガノイド、モデル動物）
- 診断・検査技術（バイオマーカー、体外診断薬、臨床検査）
- 再生医療
- バイオ生産（微生物・細胞・藻類による物質生産、発酵、培養技術）
- 動物用医薬品
- 農業・食品分野のバイオテクノロジー（培養技術、微生物利用、機能性素材の生物生産）
- 医療機器のうち治療・診断に直接関わるもの
- バイオ関連の大学発スタートアップ・研究機関

**該当しない:**
- ソフトウェア・SaaS・AIエージェント（営業支援、会議分析、コンタクトセンター、議事録、経営管理）
- 半導体、ディスプレイ、太陽電池、製造装置、外観検査
- 宇宙輸送、衛星、ロボティクス、自動運転、物流
- フィンテック、決済、金融プラットフォーム、暗号資産、トークン化
- エンタメ、IP、コンテンツ配信、広告、マーケティング
- 量子コンピューティング、エネルギー（フュージョン等）
- 人材、教育、子育て支援、自治体DX、セキュリティ、防犯

**第1段階で「該当しない」と判断したら、そこで discard とします。第2段階には進みません。**

##### 領域判定の注意（重要）

1. **本文に「創薬」「医薬品」「バイオ」等の語が出てきても、それが市場背景・用途例・
   将来の応用可能性の言及にとどまる場合は「該当しない」と判断します。**
   判断は投資先企業の事業そのものに対して行ってください。
   例: 宇宙輸送インフラの企業が「宇宙環境利用は創薬にも活用できる」と述べている場合は
   該当しません。

2. **複数社への一括出資（アクセラレータープログラムの Batch 出資など）は、採択企業の
   事業内容を1社ずつ確認します。** 対象領域の企業が1社でも含まれれば第2段階に進み、
   その企業に焦点を当てて見出しを作ります。1社も含まれなければ discard とします。

3. 投資先が明記されていない、または本文から事業内容が読み取れない場合は discard とし、
   reason に「事業内容不明」と記します。推測で該当と判断してはいけません。

4. VC 自身に関する発表（組織改正、役職新設、ファンド運営体制の変更など）は、
   投資先の話ではないため該当しません。

#### 第2段階: 掲載価値の判定

第1段階を通過したものだけを判定します。

**残す（keep）:**
- 資金調達（増資、出資受入、グラント採択のうち研究開発に直結するもの）
- 資本提携、業務提携、ライセンス契約、共同販売・共同プロモーション
- 新製品の発売・上市・販売開始
- 承認取得、承認申請、適応追加、当局による申請受理
- 臨床試験（開始・進捗・結果・中止を含む）
- 共同研究の開始・成果
- 研究成果（論文発表・発見）

**捨てる（discard）:**
- 採用・求人・インターン
- イベント・セミナー・説明会の告知
- 一般向け啓発活動・キャンペーン
- 自己株式の取得状況
- 賞・ランキング・指数銘柄選定
- 人事・役員異動・組織改正（単独の人事お知らせ）
- 定型的な IR 書類掲載のみで新規事実が乏しいもの
- 「助成金の受領に関するお知らせ」（助成金・グラントへの採択発表とは区別する）
- Q&A 資料、質疑応答
- 「払込完了に関するお知らせ」
- お別れの会・訃報・社会貢献イベント単体

**人事情報の例外:** 代表取締役、社長、CEO、CFO、CSO、EVP など経営・研究開発のキーパーソンの
就任・退任、および複数の重要幹部の任命は keep の対象になり得ます。一般的な定期人事や
部長級以下の一覧は捨てます。

### 見出しの作り方（keep のときのみ）

- 元タイトルが十分具体的なら尊重します
- 元タイトルに主語がなければ、本文から発表主体を補います
- 発表主体が多数の場合は中心となる企業・機関1者と「など」にまとめます
- 大学名は必要に応じて「○○大」のように簡潔にします
- 子会社の発表で親会社・上場会社が文脈上重要な場合は、親会社名を補います
- 共同発表者のうち、創薬・バイオ領域と関係が薄い主体は省いてよいです
- 原題の疾患名、製品名、開発コード、試験相、承認・申請・提携などの重要事実は残します

### リード文の作り方（keep のときのみ）

- 原則として、発表主体と新規事実がまとまった最初の実質的な段落を使います
- 冒頭に正式本文より簡潔で正確な要約段落がある場合は、その要約を優先してよいです
- 原文の事実、数値、固有名詞、試験相を変更しません。推測や評価を加えません
- 改行・余分な空白・明白な括弧崩れは修正してよいです
- ヘッダー、日付、問い合わせ、免責、箇条書きだけの部分はリードにしません

### 出力

JSON のみを返してください。前後に説明を付けないでください。

```json
{"decision":"keep","edited_title":"","lead":"","reason":""}
```

- `decision`: `keep` または `discard`
- `edited_title`: keep のときのみ。discard のときは空文字列

## reason の書式を固定した理由

出力スキーマは Excel の `candidates` テーブルの4列（`decision` / `edited_title` /
`lead` / `reason`）に合わせている。列を増やさずに「領域で落ちたのか、カテゴリで落ちたのか」を
後から集計できるようにするため、`reason` の先頭を `領域: 該当 — ` / `領域: 非該当 — ` に
固定した。

チューニングでこれが足りなくなったら、`candidates` に `domain_match`（真偽）と
`confidence` を追加し、出力スキーマも拡張する。

## 元コードから引き継いだもの・省略したもの

元コードでは、判定と見出し・リード編集を Claude Code が対話の中で担っていた
（`--dump-for-review` → 判定 → `--apply-review`）。そのとき Claude Code に渡していた
情報が `PendingReview`（`src/curator.py:199`）で、以下6項目だった。

| 元コードが渡していたもの | このプロンプト | 備考 |
|---|---|---|
| `original_title` | `title` | `normalize_whitespace()` は通していない。全角スペースが残るため元コードと同一文字列にはならない。判定への実害はない |
| `source_text`（上限3,500字） | `body_text` | HTML断片のまま渡す。実測1,577〜3,401字で分量は同等。`pressRelease.text` は本文フィールドそのものなので、元コードの推測セレクタ抽出よりゴミ混入・取りこぼしがない |
| `relevant_examples`（編集お手本） | **上記「編集お手本」に10件を埋め込み済み** | 元コードは `_select_examples()` で候補ごとにスコアリングして数件選んでいた。10件全部で約4,140字なので、選別せず全件渡す方式にした |
| `preselected_lead` | 省略 | PR TIMES は本文冒頭が実質的な段落なので、事前選定なしでも成立する。TDnet（PDF）へ広げる際は再検討が必要 |
| `heuristic_hint`（keep/discard/uncertain） | 省略 | ヒューリスティック層をプロンプトに統合したため |
| `heuristic_reason` | 省略 | 同上 |

**トークン消費は元コードより増える。** 元コードはハード除外と明確なキーワード除外を
LLM に到達する前に決着させていたが、この設計は全候補をプロンプトに通す。22件規模では
問題ないが、件数が増えたら事前除外の再導入を検討する。
